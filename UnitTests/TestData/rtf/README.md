# RTF test corpus

This directory holds the RTF documents used by `UnitTests/Text/RtfCorpusTests.cs` to exercise
`RtfToText`, `RtfToHtml` and the internal `RtfInterpreter` (sync/async parity).

The documents are grouped into one subdirectory per origin. Each subdirectory has a `README.md`
giving the upstream project, the exact commit the files were taken from, their original paths, and
the license they are distributed under (a copy of which sits alongside them).

## How the documents were selected

Roughly 200 RTF files from permissively licensed RTF projects were scanned for the RTF features
they exercise (control words, destinations, code pages, `\fcharset` values, `\uN` edge cases,
`\fromhtml` encapsulation, malformed structure, etc). A greedy set cover then picked the smallest
set of files that still covers every feature found, keeping the corpus small (~37 KB).

Documents that contain personal information (names, medical or legal content, obituaries, author
metadata) or third-party copyrighted prose were excluded even when they would have added coverage.
The features they would have covered are exercised by the synthetic documents in
[`mimekit`](mimekit/README.md) instead.

## Expected output

The `.rtf` files are byte-for-byte copies of the upstream files and are marked `binary` in
`.gitattributes` so that line-ending normalization never alters them.

The `<name>.txt` and `<name>.html` files next to each document are the expected `RtfToText` and
`RtfToHtml` output. They are generated by MimeKit, not taken from upstream. If a test finds that an
expected-output file is missing, it writes the current output and reports the test as
Inconclusive. To regenerate after an intentional behavior change, delete the affected files, re-run
the tests, and review the diff.
